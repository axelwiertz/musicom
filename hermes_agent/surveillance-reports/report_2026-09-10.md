### 2.1 REPLICABLE — code written this scan

- **Teaching Machines FuzzBillion** (soundonsound.com, September 2026 issue — review by William Stokes)
  Tech: A distortion device (not just a fuzz pedal) for guitar, bass and **synthesizers** with
  instrument- *and* transformer-balanced line-level I/O. 11 numerical switches, each with 10 positions
  (0–9), followed by a gain knob: "The switches relate to various diodes and amplifiers (germanium,
  silicon, LED, etc.) and each of those makes its own contribution to the overall distortion sound" →
  10^11 possible circuit variations (10 switches^11 — literally "billions"). The signal path is a
  **serial string of discrete nonlinear stages**, each chosen at build/switch time. Modelled here with
  ten real transfer functions; the diode pairs use the exact antiparallel-diode law
  `y = Vk·asinh(x/Vk)` with knees 0.30 V (germanium), 0.65 V (silicon) and 1.80 V (LED), which is why
  the switch position changes hardness of the knee rather than only gain — smaller Vk = earlier,
  softer logarithmic squeeze = brighter harmonic content.
  Replicable: **YES**
  Musicom path: `sound/effects/topology_distortion.py` (`FuzzBillion`, `TopologyStage`,
  `ELEMENTS`, `circuit_count`, `random_code`) — **SP-069**

- **ZERO9 Fusion Filter** (musictech.com, 2026-09-08, news by Emily Swingle)
  Tech: "puts five different filter characters into one workflow and allows you to filter between
  engines while using the same amount, resonance and mix controls." The replicable idea is
  **character morphing as a first-class parameter** — five genuinely distinct topologies (not five
  presets of one filter) sharing a single control set, crossfaded continuously. Implemented as:
  saturating 4-pole transistor ladder (per-stage `tanh` + feedback saturation), asymmetric diode
  ladder (`x − 0.35x²` before `tanh` → even-order colour), ZDF/trapezoidal state-variable filter
  (clean 2-pole, `a1/a2/a3` trapezoidal coefficients), resonant comb with a damping lowpass in the
  feedback path (metallic/formant character rather than a single peak), and a "scream" ladder followed
  by a Serge-style wavefolder. The morph is equal-power (`cos/sin` weights) between the two adjacent
  characters, so only two engines are ever computed.
  Replicable: **YES**
  Musicom path: `sound/effects/morph_filter.py` (`FusionFilter`, `filter_character`, `CHARACTERS`) — **SP-070**

- **ZERO9 Severed Space / Eccentric Echo / Fractured Frequency / Crushing Compressor** (musictech.com, 2026-09-08)
  Tech: four production effects from the same range, each with concrete DSP:
  *Severed Space* — "a gated reverb with **onset-triggered closure**, **spectral declashing** and final
  **analogue movement**". Implemented as a compact comb+allpass reverb tail whose gain is multiplied by
  an onset-triggered gate envelope (trigger → short hold → fast linear close), a `spectral_declash`
  stage that compresses above-threshold STFT bin magnitudes relative to each frame's mean while
  preserving phase, and an LFO movement on the tail level.
  *Eccentric Echo* — "a pair of delay engines — one **continuous** and one **granular** — capable of
  feeding into one another", with serial/parallel routing, echo, **splice**, pitch settings. Implemented
  as a fractionally-interpolated (linear) continuous delay line plus a windowed-grain engine reading the
  same line at a splice hop, coupled serially (continuous feeds granular) or in parallel, with per-engine
  pitch (read-rate) and feedback.
  *Fractured Frequency* — "a **four-stage, tempo-locked glitch chain**". Implemented as stutter
  (chunk-repeat), reverse-slice, bitcrush and decimate stages on a 16th-note grid, each gated by a
  user pattern.
  *Crushing Compressor* — "**four frequency bands** of **upward and downward parallel compression**".
  Implemented as a complementary 4-band Linkwitz-style crossover with an RMS envelope per band,
  downward gain above threshold and upward lift below a lower threshold, blended into a parallel wet path.
  Replicable: **YES**
  Musicom path: `sound/effects/severance.py` (`GatedReverb`, `DualEngineDelay`, `RhythmicGlitchChain`,
  `ParallelBandCompressor`, `spectral_declash`) — **SP-071**

- **Crow Hill Company "Brackish Pads"** (soundonsound.com, September 2026 issue — review by Paul White, 5/5)
  Tech: Each patch is **three sampled partials** — *Basic*, *Complex* and a dedicated *Critters* partial —
  re-balanced with three sliders; the identity of the instrument is "unpredictable note modulations and
  microtonal shifts" producing "a sense of **unstable pitch-wobble** creating a disturbing undertow …
  sometimes hints at a badly maintained Mellotron". Four **Pump Triggers** (coloured keys) fire different
  envelopes linked to the compressor; a **Cassette** control dials in wear; a **Splosh** reverb adds
  solidity. Implemented as: `Partial` (detuned wave stack with a **random-walk** — explicitly not
  sinusoidal — pitch wobble, integrated into phase so the detune is click-free), `Critters`
  (Poisson-process trigger times → clusters of sinusoids detuned by offsets drawn from a configurable
  microtonal set: quarter-tone, eighth-tone, just-ish, chromatic-drift, with per-cluster random drift
  and per-cluster octave selection), `pump_envelope` (four distinct attack/decay shapes),
  `cassette` (wow + flutter interpolated resample, head-loss one-pole lowpass, tape hiss, asymmetric
  `tanh` squash) and `splosh` (sparse early reflections + short comb tail).
  Replicable: **YES**
  Musicom path: `sound/synthesis/critter_pad.py` (`PadPartialBank`, `Partial`, `Critters`,
  `pump_envelope`, `cassette`, `splosh`, `MICROTONAL_SETS`) — **SP-072**

- **Muro Box N40** (synthtopia.com, 2026-09-08)

## 5. ⚠️ SP-ID namespace conflict found (record only — REPORTED, not silently fixed)

The LAYER DISCIPLINE rule says "max numeric ID in `SP_METHODS` keys ∪ `methods-registry.md` IDs, +1".
That union gives **SP-038**, but does **not** account for `docs/methods.md`, which is the *same* SP
namespace (its SP-001 = the same "Multi-timbral SoundFont" method as `SP_METHODS["SP-001"]`), and which
already occupies **SP-038 … SP-068**.

Worse, the two documents **disagree over SP-033…SP-037**:

| ID | `docs/methods.md` (absolute catalog) | `methods-registry.md` / `SP_METHODS` (surveillance replications) |
|---|---|---|
| SP-033 | Digital Waveguide Synthesis (1D/2D Wave Equation) | Detuned Saw Swarm (SuperStarSaw-style) → `sound/synthesis/supersaw_swarm.py` |
| SP-034 | Higher-Order Ambisonics (HOA) Spatialization | BBD Chorus Ensemble (Thorus XT-style) → `sound/effects/bbd_chorus.py` |
| SP-035 | GENDYN Stochastic Breakpoint Synthesis | Fractional-Pitch Shimmer Reverb (3rd Wave-style) → `sound/effects/shimmer_reverb.py` |
| SP-036 | Pulsar Synthesis | Klatt-Cascade Formant Voice (klattsch-style) → `sound/synthesis/formant_voice.py` |
| SP-037 | PSOLA Synthesis | Pitch-Tracked 3-Band Sub-Harmonic Generator (Penteo 8-style) → `sound/effects/subharmonic.py` |

Impact assessment:
- **Production is NOT broken.** `SP_METHODS` resolves each ID to a real `sound/` module, and
  `produce()` reads only that dict — the ID→module mapping is internally consistent, so nightly jobs
  keep working. (pytest: all green, 374 passed.)
- **Documentation is ambiguous** for SP-033…SP-037: two different methods share each ID. A reader
  following `docs/methods.md` to `sound/synthesis/supersaw_swarm.py` will find the wrong method.
- **This scan therefore did not reuse or renumber any existing ID.** To guarantee no new collisions I
  assigned **SP-069…SP-074**, i.e. global-max-over-all-three-docs + 1. A dedicated reconciliation pass
  is recommended (candidate: move the surveillance replications to a `RP-xxx` namespace, or renumber
  the five colliding IDs), but that is a deliberate decision for the user, not something to bury in a
  nightly commit — so the conflict is **documented in `methods-registry.md` with a ⚠️ note** and left
  for review.

## 8. PARTIAL notes (explicit — nothing faked)

1. **XILS-lab MemoryTone** — per-voice oscillator-interaction, voice-variation and mixer-level-dependent
   drive modelling would need the vendor's measured voice-to-voice tolerance data. Existing
   `memorymoog_synth.py` covers the architecture (3-osc stack, whole-tone detune, 4-pole saturating
   ladder); the MPE per-note brightness and arpeggiator were left out.
2. **TONE3000 / NAM** — neural amp captures are trained model weights (hundreds of MB, vendored in the
   original). No inference stack exists in the repo and one was NOT stubbed. Needs an explicit decision +
   a torch/ONNX dependency before any code is written.
3. **ZERO9 Reactive Reverb** — the "input-reactive" mapping (which parameters react to which input
   features, and how strongly) is not published; only the structural behaviour (envelope/onset-driven
   reshaping) was implemented, inside SP-071.
4. **MixWave Spiritbox** — an artist-preset chain; all constituent DSP already exists in the repo, so
   writing a duplicate module would have been dead code. Not registered (no new SP-ID).
5. **Sauceware Scorch 2** — the Chaos macro and the scale-snapped 3-track generator are genuinely
   algorithmic and are a **candidate for a future scan**; they were not built now because the closest
   existing modules (`math_mod.py`, `scale_quantizer.py`) already cover the primitives and the remaining
   value is in the curated multi-synth sample content, which cannot be replicated.
6. **Waveform 14 Pro / Logic 12.3 stem separation** — requires trained separation models (demucs-class);
   still tracked as the planned `sound/transcription/separation.py`. Not attempted.
7. **Vintage Emulator Studio** — MAME machine emulation of vintage hardware; the ROM images are
   deliberately not distributed and are legally user-supplied. No DSP to replicate.
8. **SP-033…SP-037 ID collision** — see §5. Documented, not silently renumbered; no SP-ID was reused or
   blown away by this scan.
