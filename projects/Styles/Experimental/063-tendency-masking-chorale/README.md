## Concept

An 8-bar homophonic chorale in **D minor (aeolian)** — `i - VI - III - VII` (Dm - Bb - F - C) — whose soprano contour is generated by the **Tendency Masking Stochastic Bounds** method: pitches are drawn stochastically from the D-aeolian pool, but only inside a *dynamic frequency envelope* that glides between a start and end register over each section. Rising envelopes produce arching growth phrases; falling envelopes produce relaxation. The raw stochastic draft is then forced through musicom's harmonic + voice-leading rule layer so the output is coherent, not mathematically interesting but musically random.

## Two-Phase Architecture

### Phase 1 - Generative draft (raw, pre-harmonic)

- **Pitch DNA (tendency masking):** `TendencyMaskingGenerator` walks 16th-note slots (480/4 = 120 ticks). At each slot the lower and upper bounds interpolate linearly from `bounds_start` to `bounds_end`, and a pitch is drawn uniformly from the D-aeolian pool inside the current window (probability 0.75). The raw contour is chord-agnostic — it only knows the key pool and the envelope.

### Phase 2 - Musicom rules post-processing

1. **Chord-tone quantization:** each raw tendency-masked pitch is snapped to the nearest tone of the section's diatonic triad (soprano register 64-86) -> consonant, key-aware melody.
2. **Diatonic block harmony:** Alto/Tenor/Bass filled from the triad via the canonical `Scale7ChordDegree.get_diatonic_note()` helper — 0-based degree indexing (index 0 = tonic), so no off-by-octave `% 7` wrap errors (this run deliberately corrected the off-by-one found in the 060/062 lineage: their `SECTION_DEGREES=[1,5,6,4]` actually produced `ii-VII-I-VI`, not the documented `I-V-vi-IV`).
3. **Voice-leading optimization:** `VoiceLeadingRules.optimize_voice_leading()` rotates inversions to minimize total voice-leading distance.
4. **Harmonic progression rule:** `i - VI - III - VII` verified against `PatternMovementRules.movement_rules` and the `Scale7ChordDegree` function map (i tonic -> VI/III tonic-prolongation -> VII dominant -> i tonic). VII->i is the authentic aeolian cadence (C major -> D minor).
5. **Zero-drift gate:** `UnitMatrixComposer.validate()` passed before `to_midi()`; deterministic seed (23) -> byte-reproducible artifact.

- **Zero-drift:** PASS — all 4 voice tracks end at exactly **15360 ticks** (8 bars × 1920). Verified independently with mido: track lengths `[0, 15360, 15360, 15360, 15360]`. Each section cell is landmark-padded to its declared 2-bar boundary (3840 ticks) so the composition spans a clean 8 bars with zero cumulative drift.

- **Voice pitch ranges:** Soprano 64-74, Alto 53-64, Tenor 57-67, Bass 38-48 — SATB registers respected, no crossings.
- **Voice-leading (classical strictness):** 2 residual flags on the i->VI transition — the textbook **parallel fifths** (D-F-A -> Bb-D-F shares the F as fifth of Dm and root of Bb; root and fifth move in parallel) and the resulting hidden fifth in the outer voices. This is the genuine trap the rule system is designed to surface — reported honestly, not suppressed. Block homophony makes it structurally unavoidable without non-chord tones or a `pop`/`jazz` style.
- **Harmonic rules:** i-VI-III-VII conforms to `PatternMovementRules` minor-mode legality; VII->i is a valid dominant->tonic resolution in aeolian.
