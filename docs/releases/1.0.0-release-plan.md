# Musicom 1.0.0 Release Plan

## Goal
Publish `musicom` 1.0.0 as a **single, simple educational repository** — a
composition + production + analysis library that ships together with a
Hermes-agent skill. No public/private repo split, no archive mechanism: one
repo, every folder clearly labeled for what it contains and who it's for.

## Decisions (from user)
1. **No public/private split.** Educational repo stays simple and self-contained.
2. **Clarity over separation.** Replace the split with a single *repository map*
   (`REPO_MAP.md`) + folder-level READMEs that say exactly what lives where.
3. **Living corpus is a feature, not a leak.** `projects/` is nightly-synced by
   the host cron and autopushed — document it, don't fight it. Keep heavy/derived
   artifacts (`*.wav`, `*.log`, `outputs/`) out of git.
4. **Reverse analysis is first-class.** README currently forward-only; add the
   reverse/decomposition path as a symmetric pipeline.
5. **Skill framing.** Codebase runs together with a Hermes agent — publish it
   explicitly as a skill.
6. **Agent manual.** Add `docs/AGENT_MANUAL.md` + root `CLAUDE.md` for code
   agents (Claude, Hermes) using the code + MD files.

## Data flow (post-1.0.0)
- Forward: `compose()` / `UnitMatrixComposer` → `validate()` gate → MIDI +
  provenance → `produce(SP-001/SP-011/...)` → WAV → OGG.
- Reverse: MIDI/audio file → `analyze_midi()` (mido READ + harmony/set-theory +
  grid) → report (key, roman progression, Forte names, violations, density) →
  optional `project_to_score` (opt-in music21) for notation.
- Failure modes: stub `midifile_to_piece` (do not use — replaced by
  `analyze_midi`); `score_analyze` plotting (never call headless); empty MIDI
  (assert size >40B); unequal rows (pad via `_unit_from_events` pattern);
  missing SoundFont (use `discover_soundfont()`); musicpy/music21 eager import
  (keep lazy, pinned by `test_generator_lazy_imports`).
